客户列表

客户列表

客户姓名唯一且可修改；修改后同步替换业务配置及归属上级中的客户姓名。共有信息默认展示备注摘要；点击可查看全文。询价配置、常规期权和孖展合约统一进入同一个客户业务配置窗口，通过三个 Tab 切换；多个客户仍可分别打开并最小化，合同业务群编号独立维护。

归属链路固定展示一级至五级五个位置，每个位置显示级次和客户名；无值显示“-”，不因省略空级次而重新编号。点击列表工具区的“客户关系图”，可查看全部客户组织结构，并按客户姓名搜索定位；仍保留一级至五级节点筛选。导出覆盖当前筛选的全部匹配客户。

操作列沿用现有页面的五个常显按钮与配色：询价、常规期权、杠杆合约、修改、删除，不收进“更多”；前三个按钮打开统一窗口并快速定位对应 Tab。此处“杠杆合约”为旧页面按钮文案，指向孖展合约配置；业务字段及其他页面继续使用已确认的“孖展合约”。

客户共有数据导入

单次最多 500 条。文件按顺序逐行预览；同文件重复姓名，或后序新增客户引用先序新增客户为上级时，后序行解析失败，原因“与第 X 条互斥”。其他通过行可以执行，失败行修正后重新上传。

新增时空上级代表顶级；更新时空值表示不修改。执行仍须复核校验，不保证预览通过必然执行成功。

业务配置导入

按客户姓名匹配已有客户；常规期权和孖展合约工作簿均分“主配置”和“返佣/提成明细”两表，两表数据行合计不超过 500。主配置重复客户时后序行提示“与第 X 条互斥”。

常规期权有中间人前后端返佣、员工前后端提成四类，明细填写姓名、比例、按明细类型匹配的返佣规则和说明：中间人前端为公司加点、公司加点-交易成本、咨询费、咨询费-交易成本；中间人后端为税金、税金-交易成本；员工前端为公司加点、公司加点-交易成本、咨询费、咨询费-交易成本、咨询费-中间人咨询费返佣、咨询费-交易成本-中间人咨询费返佣、中间人加点剩余部分；员工后端为税金、税金-交易成本。孖展合约主配置仅包含群编号、归属员工和直接对接人；六类明细为中间人认购费、续期费、投资者分成返佣及员工对应三类提成，仅填写姓名、比例、说明，不设返佣规则。比例为 0-100%，最多两位小数，0 有效。所有返佣和提成明细的姓名均为手填文本，不匹配员工数据字典；同一明细类型下允许添加多个相同姓名。

文件中出现的“客户＋明细类型”整组替换，未出现的类别不修改；一行无效则整组失败并保留旧值。主配置成功不受明细组失败影响。已有主配置可只导入明细；没有主配置时提示先建立。普通空白不清空旧值，清空方式待确认；停用群人工核验。

询价配置使用单表，一位客户在同一文件中至多一行，按姓名绑定已有客户。报价分类ID须匹配系统【报价分类】字典；公司、中间人、行情额外加点各拆为大陆和香港两列，单位为%。重复客户后序行互斥，格式或字典校验失败的行不执行；通过行新增或更新配置。加点的上限、精度及新增空值规则待确认，演示ID不代表系统真实字典。

导入文件中心

系统级汇总各模块导入批次；新产生的原始文件长期保留，不设有效期。重新上传产生新批次，最新批次结果不与旧批次合并，也不回滚旧批次已成功写入的数据。

正式实现需支持查看/下载原文件、结果和失败行文件。历史文件只在原件与批次信息可取得时回补。

客户数据导出

导出当前筛选条件下的全部匹配客户，不按勾选或当前页。总览主表一行一客户，使用共有信息、常规期权、孖展合约和询价配置分组表头；保留返佣/提成条数，并在同一文件中附上选中业务的完整返佣提成明细工作表。

导出页面直接展示示例文件的表头与数据，可切换工作表。明细工作簿包含客户共有数据、两类合同各自的主配置和返佣提成明细、询价配置、字段说明；按字段分组选择保留相应工作表。明细一条一行，允许同名，不去重，各表以客户姓名关联。

导出字段和数据范围遵守现有权限；备注完整导出，未配置业务明确标注“未配置”。

多客户工作窗口

询价配置、常规期权、孖展合约合并为一个客户业务配置窗口，以客户作为窗口唯一标识。列表三个按钮和现有样式保留，点击后打开或恢复同一窗口并进入对应 Tab；不同客户仍可分别打开。

“修改”在当前窗口切换到编辑，不叠加详情弹窗；保存后回到详情，取消不保存。多个窗口可切换、最小化和恢复，宽屏最多并排显示两个；任务栏显示客户姓名、业务类型和当前状态。最小化保留未保存输入；关闭未保存窗口须确认放弃。

备注在详情内展开；主配置与返佣/提成明细始终同时展示。每个明细类型旁单独提供新增按钮，点击后在该类型下展开表单，所属类型固定，不再选择明细类型；常规期权返佣规则自动对应当前类型。新增、修改不替换主配置，两处分区可同时编辑，分别保存或取消，互不丢弃草稿。最小化及切换客户保留草稿，带未保存内容切换业务 Tab 或关闭窗口时先确认放弃；短确认不承载完整表单。

三个 Tab 字段与导入项目一致，支持同窗查看和编辑。常规期权四类明细包含姓名、比例、对应返佣规则、说明；孖展合约六类明细没有返佣规则。明细姓名全部手填，同一类别允许多条同名记录，不匹配员工字典；主配置的归属员工、直接对接人均为员工管理下拉，原型使用预置示例。尚无主配置也可先填写明细，保存明细时才检查主配置；提示后保留输入，补充并保存主配置后可继续保存明细。导入仍保留明细类型字段，按原主配置依赖规则执行。询价未配置时直接显示报价分类ID及大陆、香港各三项加点的空白表单，无须点击新增，保存通过后才建立配置；正式数值边界仍待确认，示例字典和保存均为本地演示。

    # 客户管理 UI 样式及易用性优化

版本：V1.0
日期：2026-11-02
关联简报：[客户管理_UI样式及易用性优化_需求简报](./客户管理_UI样式及易用性优化_需求简报.md)

## 1. 功能说明

优化客户管理的列表展示、业务详情/编辑窗口交互、客户批量导入和数据导出能力。客户共有信息继续由客户主数据统一维护，常规期权、孖展合约和询价配置按业务类型导入；合同业务配置仍按分组展示，避免在有限屏幕下平铺过多字段。

本需求包含客户列表、业务详情多窗口交互、客户共有数据导入、业务配置导入、导入文件中心和客户数据导出；不包含生产接口、数据库迁移实现、权限系统重做或真实客户数据操作。

## 2. 需求详细说明

### 2.1 页面入口与前置条件

| 模块 | 需求项 | 规则说明 |
|---|---|---|
| 客户管理 | 页面入口 | 从“信息管理-客户管理”进入，保留现有客户列表、添加、编辑、删除、回收站和业务详情入口。 |
| 客户主数据 | 客户姓名唯一 | 客户姓名不可重复，是共有数据导入的匹配键。 |
| 客户主数据 | 客户姓名修改 | 允许修改；新姓名需通过格式校验且不能与其他客户重复。保存后同步更新常规期权、孖展合约和询价配置中的客户姓名，并同步替换归属上级引用；客户内部关联保持不变。若关联信息无法同步更新，本次改名整体失败，原姓名保持不变。 |
| 客户主数据 | 新增/更新 | 导入文件中的客户姓名不存在时新增；已存在时更新该客户共有字段，不生成第二条同名客户。 |
| 客户主数据 | 权限 | 沿用现有权限系统，本需求不新增或重做权限控制。 |
| 业务配置 | 业务类型 | 导入业务配置可选“常规期权”“孖展合约”“询价配置”。询价配置不产生第三种合同业务类型，也不改动既有询价记录。 |
| 业务配置 | 配置关系 | 一个客户可以同时配置两类业务；每类业务的主配置最多一条。常规期权四种、孖展合约六种返佣/提成具体明细类型均各自允许多条。 |
| 询价配置 | 客户关联 | 按唯一客户名称绑定已有客户；本次导入文件中每位客户至多一行，已存在配置更新，不存在时新增。报价分类ID须匹配系统【报价分类】数据字典。 |
| 群编号 | 业务归属 | 现有 `group_id` 按常规期权群编号理解；新增独立的孖展合约群编号。 |
| 群编号 | 复用与停用 | 群编号允许多个客户复用；停用群状态由人工核验，本需求不新增系统感知。 |

### 2.2 客户层级规则

| 规则编号 | 规则 |
|---|---|
| R-01 | 新增或更新客户时只维护“归属上级”字段，不直接填写一级至五级归属名称。 |
| R-02 | 单条新增/编辑时“归属上级”为空表示顶级客户；共有数据导入新增行为空也表示顶级，更新行为空则按“不修改已有值”处理。更新时若要改成顶级，需在单条编辑页清空上级。 |
| R-03 | 一级至五级归属优先使用系统已有的级次字段；无级次字段时再根据客户父子关系推导。列表、树状视图和导出使用同一口径，空级次保留位置并显示“-”。 |
| R-04 | 归属上级按客户姓名匹配；上级不存在、指向自身、形成循环或超出系统层级限制时，数据不得执行。 |
| R-05 | 导入新增客户时，不得以同一文件内新增的其他客户作为“归属上级”。若两条记录形成这种同批次引用关系，按文件顺序将后出现的互斥记录标为行解析失败，原因显示“与第 X 条互斥”（X 为先出现记录的数据序号）；先出现的记录仍需独立通过上级存在、层级等校验。系统不调整行顺序以建立该归属关系。 |

### 2.3 客户列表信息架构

列表采用“客户共有信息 + 业务摘要 + 操作”结构。

| 区域 | 默认展示 |
|---|---|
| 客户共有信息 | 客户姓名、状态、授信金额、备注摘要、归属链路 |
| 询价配置摘要 | 是否配置、报价分类ID、公司/中间人/行情额外加点摘要 |
| 常规期权摘要 | 是否配置、常规期权群编号、归属员工、直接对接人、业务属性摘要 |
| 孖展合约摘要 | 是否配置、孖展合约群编号、归属员工、直接对接人、业务属性摘要 |
| 操作 | 询价、常规期权详情、孖展合约详情、修改客户共有信息、删除 |

列表规则：

- 业务分组从左至右固定为“询价配置 → 常规期权 → 孖展合约”，位于共有信息之后、操作列之前；
- 备注属于共有信息，默认展示摘要；空值显示“-”，点击摘要可查看完整内容，长备注不撑高列表行；
- 一级至五级归属固定展示为五个位置，每个位置显示实际级次和名称；空节点显示“-”，不能因省略空级次而重新编号；
- 列表不省略五级位置；长名称在格内摘要显示，完整路径可通过悬停或全局树状关系视图查看。列表工具区提供唯一的“客户关系图”入口，不在每行重复设置按钮；打开全部客户的组织结构树，不受当前列表筛选和分页限制。支持展开/收起分支；按客户姓名模糊搜索时显示匹配结果并高亮图中节点，点击结果展开祖先分支、滚动定位并展示该客户五级路径；搜索无结果时给出提示，不清空关系图。关闭后保留原列表筛选与页码；
- 树状视图仅根据已建立的客户父子关系生成，不补造缺失祖先；如果存量数据只有四级、五级字段而上级链条不完整，仍应保留原始级次，实际映射方式需核对现有数据口径，不能擅自改为一级、二级；
- 仍需支持按一级至五级归属节点筛选，视觉合并不能删除查询能力；
- 未配置业务时显示“未配置”，不使用空白；
- 常规期权业务属性摘要直接展示通道费率、税金；如已有返佣/提成明细，补充展示明细条数；
- 孖展合约业务属性摘要与常规期权保持一致，直接展示“返佣/提成 N 条”；完整明细类型、姓名、比例和说明仍从业务详情查看；
- 询价配置摘要直接展示报价分类ID，以及公司、中间人、行情额外加点的大陆/香港值；加点值按 `0.00%` 展示，未配置显示“未配置”，配置存在但字段为空显示“-”；

### 2.5 客户共有数据导入

入口：客户管理 → 导入客户。

流程：

`下载模板 → 上传文件 → 解析 → 逐行预览校验 → 执行通过行 → 查看结果 → 修正失败行后重新上传`

规则：

- 单次最多导入 500 条数据；
- 预览阶段不创建客户、不修改客户字段、不改变客户层级；
- 校验通过的行才进入执行；
- 行解析失败或校验失败的行不执行，操作员可查看失败原因并重新上传修正文件；
- 同名客户执行更新，不生成重复客户；
- 同一文件出现重复客户姓名时，按文件顺序保留先出现行的独立校验结果；后出现行标为行解析失败，提示“与第 X 条互斥”，不执行该行；
- 重新上传完整文件时，已存在客户按更新处理，不重复创建；
- 导入失败行不自动进入正式客户数据，也不产生半成品客户；
- 更新字段为空时表示“不修改已有值”，不能用普通空白覆盖已保存内容。

### 2.6 业务配置导入

入口：客户管理 → 导入业务配置。

流程：

`选择业务类型 → 下载对应模板 → 上传文件 → 按客户姓名匹配 → 预览校验 → 执行通过项（合同业务主配置行及明细整组，或询价配置行） → 查看结果 → 修正失败内容后重新上传`

规则：

- 首步必须选择业务类型：常规期权、孖展合约或询价配置；前两种为双表工作簿，询价配置为单表工作簿；
- 业务配置导入只允许匹配已有客户，不自动创建客户；
- 客户姓名不存在时，该行校验失败；
- 已存在同一业务主配置时更新，不存在时新增；两种业务的明细均按“客户姓名 + 明细类型”整组替换，不采用逐条更新；
- 同一文件的主配置表中同一客户重复时，按文件顺序保留先出现行的独立校验结果；后出现行标为行解析失败，提示“与第 X 条互斥”。两种业务的明细表均允许同一客户同一类型出现多条相同或不同姓名，不套用主配置的互斥规则，也不按姓名去重；即使姓名相同仍分别保留各行；
- 孖展合约及常规期权主配置只执行校验通过行；两种业务的明细只执行校验通过的整组，同组任一行失败则整组不执行；
- 询价配置按客户逐行校验及执行；同一文件内客户名称重复时，后序行标为行解析失败并提示“与第 X 条互斥”，先序行仍独立校验。报价分类ID不在系统【报价分类】字典内、客户不存在或百分比字段格式不合法的行失败，不影响其他通过行。通过行新增或更新该客户的询价配置，不创建询价单，也不修改两种合同业务配置；
- 失败行由操作员修正后重新上传；
- 重新上传完整文件时，已存在客户/业务配置按更新处理，不重复创建；新批次结果直接作为最新结果，不与旧批次合并，也不撤销旧批次已成功写入的数据；
- 执行阶段仍需复核客户、业务类型和引用数据，不能只信任预览结果。

| 姓名 | 必填；全部按手填文本处理，不匹配员工数据字典；同一明细类型允许填写相同姓名。 |
| 比例（%） | 必填；数值范围 `0` 至 `100`（含两端），最多两位小数；`0` 是有效值，不能视为空。 |
| 返佣规则 | 必填；按明细类型使用对应枚举：中间人前端返佣允许“公司加点”“公司加点-交易成本”“咨询费”“咨询费-交易成本”；中间人后端返佣允许“税金”“税金-交易成本”；员工前端提成允许“公司加点”“公司加点-交易成本”“咨询费”“咨询费-交易成本”“咨询费-中间人咨询费返佣”“咨询费-交易成本-中间人咨询费返佣”“中间人加点剩余部分”；员工后端提成允许“税金”“税金-交易成本”。 |
| 说明 | 选填；与当前明细行一一对应。 |

- 同一客户的同一明细类型可有多条记录，姓名允许重复；四种类型彼此独立，同一姓名可出现在不同类型。
- 某客户某类型的明细只要在文件中出现，即以**该类型本次全部有效行**整体替换原有整组；没有出现的类型保持原值。普通空白不表示清空整组；清空已有整组需要明确清空操作或清空标记，具体入口/标记形式待确认。
- 一组内任意行的姓名、比例或对应明细类型的返佣规则不通过时，**该客户该类型整组失败且不替换旧数据**；其他客户或该客户的其他明细类型仍可通过。预览和失败文件同时标明组结果、各 Excel 行及具体失败原因，不能把同组其余行当作可单独执行。
- 主配置与明细独立处理：主配置通过后可新增/更新，即使同一客户某明细组失败，主配置和其他有效组仍成功；主配置创建失败时，依赖该主配置的明细组不得执行。已有常规期权主配置允许只导入明细，主配置表保留表头但不产生更新；客户尚无该业务主配置、文件中也没有成功建立主配置时，明细组失败并提示“请先建立常规期权主配置”。同一文件可先成功建立主配置，再执行该客户通过校验的明细组。

#### 2.7.3 孖展合约模板

使用一个 `.xlsx` 工作簿，包含“主配置”和“返佣/提成明细”两张工作表。两表的数据行合计最多 500 行（不计表头）；“主配置”可只有表头，用于已有孖展合约主配置的客户单独导入明细。两张工作表均需具备规定表头，不以缺少工作表代替空表。

**主配置**（每位客户至多一行；返佣/提成不在主配置中保存为单值）：

| 字段 | 规则 |
|---|---|
| 客户名称 | 必填；匹配已有客户，不存在时该行失败；同文件主配置重复客户，后序行提示“与第 X 条互斥”。 |
| 孖展合约群编号 | 校验数据项在系统中存在；允许复用。 |
| 归属员工 | 校验值在系统【员工管理】字典中存在。 |
| 直接对接人 | 校验值在系统【员工管理】字典中存在。 |

**返佣/提成明细**（每行一条；按中间人返佣和员工提成两类展示，具体有六种独立的明细类型）：

| 字段 | 规则 |
|---|---|
| 客户名称 | 必填；须匹配系统已有客户。 |
| 明细类型 | 必填；中间人返佣仅允许“中间人认购费返佣”“中间人续期费返佣”“中间人投资者分成返佣”；员工提成仅允许“员工认购费提成”“员工续期费提成”“员工投资者分成提成”。六种类型各自独立。 |
| 姓名 | 必填；全部按手填文本处理，不匹配员工数据字典；同一明细类型允许填写相同姓名。 |
| 比例（%） | 必填；数值范围 `0` 至 `100`（含两端），最多两位小数；`0` 是有效值，不能视为空。 |
| 说明 | 选填；与当前明细行一一对应。 |

孖展合约明细**没有返佣规则字段**，不得沿用常规期权的“名义本金/名义本金扣成本”必填校验。

- 同一客户的同一明细类型可有多条记录，姓名允许重复。不同明细类型互不占用名额，同一姓名可出现在不同类型。
- 某客户某具体明细类型只要在文件中出现，即以该类型本次全部有效行整体替换其旧组；没出现的类型保持原值。这里的整组不是“中间人返佣三类合并成一组”或“员工提成三类合并成一组”。普通空白不表示清空整组；清空入口或清空标记待确认。
- 一组内任意行缺姓名/比例或比例不合法时，该客户该类型**整组失败且旧组不变**；其他类型可独立通过。预览和失败文件须包含组结果、每条 Excel 行号及具体致错原因，组内未致错行也不单独执行。
- 主配置与明细独立处理：主配置通过可新增/更新，即使同一客户明细组失败，主配置和其他有效组仍成功；主配置创建失败时依赖它的组不执行。已有孖展合约主配置允许只导入明细；客户尚无主配置且本次也未成功建立时，明细组失败并提示“请先建立孖展合约主配置”。同文件可先建立主配置，再执行该客户通过校验的明细组。

两种业务的主配置更新时模板空值表示“不修改已有值”；明细以“该具体类型未出现”为不修改，已出现的类型按各自整组处理。如需清空已有值或整组，需使用单独的清空操作或明确的清空标记，不以普通空白表达。

#### 2.7.4 询价配置模板

使用一个 `.xlsx` 工作簿，包含“询价配置”工作表；单次最多 500 条数据行（不计表头）。每行绑定一位**已有客户**，同一文件的客户名称不可重复。

| 字段 | 规则 |
|---|---|
| 客户名称 | 必填；按唯一名称匹配系统已有客户，不存在时该行失败；文件内后序同名行提示“与第 X 条互斥”。 |
| 报价分类ID | 必填；按 ID 精确匹配系统【报价分类】功能的数据字典值，不在字典内时该行失败；原型中的示例 ID 不代表系统真实数据。 |
| 公司加点-大陆（%） | 单独的百分比字段，不能与香港值合并。 |
| 公司加点-香港（%） | 单独的百分比字段，不能与大陆值合并。 |
| 中间人加点-大陆（%） | 单独的百分比字段，不能与香港值合并。 |
| 中间人加点-香港（%） | 单独的百分比字段，不能与大陆值合并。 |
| 行情额外加点-大陆（%） | 单独的百分比字段，不能与香港值合并。 |
| 行情额外加点-香港（%） | 单独的百分比字段，不能与大陆值合并。 |

- 填写的加点值须能按百分比数值解析；不能把 `0` 当空值，也不将表格中的百分数再次乘以或除以 `100`。六个字段分别校验，失败时定位到具体地区及加点项。本次尚未确认允许的正负范围、最高值、小数精度、六项是否必填，以及新增配置遇空值的处理，见第 6 节；原型仅用预置有效/格式错误案例表达流程，不作为这些规则的生产校验实现。
- 已有配置按客户名称更新，更新行的加点字段空白表示不修改该字段；报价分类ID仍须提供有效字典值。未出现在文件中的客户及其配置不修改。执行阶段复核客户和报价分类字典，失败行保留旧配置；成功行不产生询价记录。

### 2.8 导入预览与状态

| 状态 | 含义 | 可执行 |
|---|---|---|
| 解析失败 | 文件结构、表头或基础格式无法解析 | 否 |
| 行解析失败 | 个别行与同文件前序记录互斥，明确提示“与第 X 条互斥” | 否；不影响其他通过行执行 |
| 校验失败 | 客户姓名、格式、层级、引用数据或业务明细组不符合规则 | 否；明细组内任一行失败时整组不可执行 |
| 校验通过 | 当前预览时点通过校验 | 是 |
| 执行中 | 正在处理通过行 | 否，禁止重复执行 |
| 导入成功 | 该行已完成新增或更新 | 否，已完成 |
| 执行失败 | 执行阶段发生错误，未完成该行结果 | 按失败结果处理，禁止显示为成功；不提供单行重试，重新上传后以最新批次结果为准 |

预览页至少展示：

- 原始文件名、导入类型、业务类型（如适用）；
- 总行数、通过行数、失败行数；常规期权、孖展合约按两张表数据行合计，整组失败的所有行计入失败行数；询价配置按单表数据行统计；
- 工作表名称和逐行 Excel 行号；
- 客户姓名；
- 关键导入字段；
- 校验结果和失败原因；
- 可执行行数。

常规期权及孖展合约均分别预览主配置逐行结果及明细的客户、具体类型、组结果、组内行明细；组内须能定位哪一行导致整组失败。执行数按“通过的主配置行 + 通过的明细组”计，文件中心行数仍按数据行计；执行结果分别展示主配置成功/失败行数及明细成功/失败组数。执行阶段主配置与每个明细组分别复核，主配置失败不得执行依赖它的明细组；失败组原有数据保持不变。无可执行项时禁用执行按钮。

询价配置预览按行展示客户名称、报价分类ID、三组大陆/香港加点、执行方式、状态和具体失败原因；执行按钮计通过行数。执行结果分别统计新增、更新和失败，文件中心保留每行原始行号及失败原因；没有通过行时禁用执行按钮。

### 2.9 统一导入文件中心

导入文件中心独立于客户列表页面，作为系统级“导入文件中心”汇总所有业务模块的导入文件。

规则：

- 所有导入文件长期保留，无有效期限制；
- 首期统一使用 `.xlsx` 模板文件；单次最多 500 条，文件大小上限暂按 10MB 设计；超出任一限制时不得进入解析执行；
- 模板带有版本标识；不支持的版本阻止导入，并提示下载最新模板；
- 原始文件不得被后续修正文件覆盖；
- 重新上传的修正文件创建新批次并与原批次建立关联；新批次结果作为最新结果，不与旧批次合并，也不回滚旧批次已成功写入的数据；
- 查看和下载范围沿用现有业务数据权限；
- 记录导入模块、导入类型、业务类型、原始文件名、文件大小、上传人、上传时间、批次号、总行数、通过行数、失败行数和最终状态；
- 失败文件统一导出为 `.xlsx`，保留原始字段，并追加“工作表、原始行号、校验状态、失败原因”字段；两种合同业务明细另附组结果，整组失败时保留同组全部原行及具体致错行；询价配置按失败行导出；
- 支持查看/下载原始文件、失败行文件和结果文件；
- 文件中心上线后，新产生的导入文件全部纳入；历史文件仅在原始文件和批次信息可取得时回补，不为缺失文件补造下载内容；
- 文件中心建议归入系统级数据管理入口，支持按模块、导入类型、业务类型、状态、上传人和时间筛选。

### 2.10 导出

入口：客户管理 → 导出。

导出范围固定为用户当前筛选条件下的全部匹配数据：

- 不按当前页限制；
- 不提供勾选客户导出；
- 导出前展示筛选条件、字段分组和预计客户数，各工作表分别展示自己的数据行数；
- 导出结果必须与当前数据权限一致。

导出模式：

1. **客户总览导出**：总览主表一行一个客户，使用共有信息、常规期权、孖展合约、询价配置四组表头。共有信息包含客户姓名、状态、授信金额、完整备注、归属上级和独立的一级至五级归属；常规期权包含配置状态、群编号、归属员工、直接对接人、通道费率、税金、返佣/提成条数；孖展合约包含配置状态、群编号、归属员工、直接对接人、返佣/提成条数；询价包含配置状态、报价分类ID和大陆/香港的公司、中间人、行情额外加点，共六列加点。除总览主表外，同一工作簿必须附上所选合同业务的完整返佣提成明细，不能只导出条数。常规期权和孖展合约均选中时，共包含“客户总览”“常规期权返佣提成明细”“孖展合约返佣提成明细”三张工作表，明细表字段与下表相同。
2. **业务配置明细导出**：共有数据、主配置和多条明细分表，通过客户姓名关联。完整勾选三个业务组时包含以下七张工作表：

| 工作表 | 表头/内容 | 数据行口径 |
|---|---|---|
| 客户共有数据 | 客户姓名、状态、授信金额（万元）、备注、归属上级、一级归属至五级归属 | 一行一位匹配客户。 |
| 常规期权配置 | 客户姓名、配置状态、群编号、归属员工、直接对接人、通道费率（%）、税金（%） | 一行一位匹配客户；无主配置时标记“未配置”，业务值为“-”。 |
| 常规期权返佣提成明细 | 客户姓名、明细类型、姓名、比例（%）、返佣规则、说明 | 一行一条已保存明细；四类明细在同表按类型区分。 |
| 孖展合约配置 | 客户姓名、配置状态、群编号、归属员工、直接对接人 | 一行一位匹配客户；无主配置时标记“未配置”，业务值为“-”。 |
| 孖展合约返佣提成明细 | 客户姓名、明细类型、姓名、比例（%）、说明 | 一行一条已保存明细；六类明细在同表按类型区分，不包含返佣规则字段。 |
| 询价配置 | 客户姓名、配置状态、报价分类ID、公司加点·大陆（%）、公司加点·香港（%）、中间人加点·大陆（%）、中间人加点·香港（%）、行情额外加点·大陆（%）、行情额外加点·香港（%） | 一行一位匹配客户；未配置时业务值为“-”。 |
| 字段说明 | 工作表、字段、数据格式、说明 | 只说明本次选中工作表中的字段。 |

示例文件预览：

- 导出页面直接展示文件样式、工作表名、表头和示例数据，不只描述工作表结构。原型使用当前本地演示客户，与当前已生效筛选同步，不引入真实客户数据。
- 总览示例为 `客户总览_示例.xlsx`，明细示例为 `客户业务配置明细_示例.xlsx`；文件名用于表达样式，原型不据此宣称已生成真实文件。
- 支持点击工作表及使用左右方向键、Home、End 切换；宽表可横向滚动，长说明可完整阅读。
- 取消某业务分组时，总览移除该组列及附带的返佣提成明细表，明细模式移除该业务的主配置、明细工作表及对应字段说明；总览主表或客户共有数据表始终保留。
- 两种模式均导出完整返佣/提成明细，按客户姓名关联；常规期权导出客户姓名、明细类型、姓名、比例、返佣规则、说明，孖展合约导出客户姓名、明细类型、姓名、比例、说明。总览的条数为已保存明细数量，仅作为摘要；同类型、同姓名的多条规则分别计数并逐条输出，即使整条内容相同也不合并、不去重。
- 某客户无明细时不补造空明细行；选中客户均无明细时保留对应工作表表头。筛选无匹配客户时显示空态并禁用生成，正式导出不生成空文件。
- 切换模式、字段分组或重新进入页面后清除旧的生成结果，防止误认为原结果已包含新条件。

导出格式：

- 客户总览第 1 行为业务分组、第 2 行为字段表头、第 3 行起为数据；业务明细各工作表第 1 行为字段表头、第 2 行起为数据。
- 金额以万元为单位；比例字段在表头注明“（%）”，预览显示两位小数，例如 `1.50` 表示 `1.50%`，不得额外乘以 100；询价加点的业务精度约束仍按待确认项处理，展示格式不修改已保存值。
- 群编号、报价分类ID及姓名按文本处理，保留前导零；0 是有效值，不能按空值处理。备注和说明输出全文。
- 五级归属保留全部级次列，空值输出“-”，不将有值级次向前补位。
- 业务未配置时显示“未配置”；
- 不默认导出内部数据库 ID；
- 导出记录操作员、时间、筛选条件和字段模板。

## 6. 待评审项

1. 是否需要在共有数据模板中支持批量改名；当前方案允许客户编辑页改名，导入仍按文件中的客户姓名匹配已有客户。
2. 若存量数据中一级至三级为空、仅四级和五级有效，需核对其与“归属上级”关系的实际映射。页面保留原始级次，不自动把四级、五级重编为一级、二级，也不补造缺失上级。
3. 两类业务明细整组清空的操作入口或明确清空标记格式尚未确定；普通空白、缺行及缺少该类型均不得视作清空指令。
4. 询价配置六个加点值的正负范围、上限、小数精度和是否全部必填，以及新增配置遇空值如何处理尚待确认；正式校验不得从常规期权返佣比例规则直接推断。询价配置与存量询价数据中“报价分类ID”的关联方式需以现有数据模型核对。

## 7. 常规期权导入验收要点

1. 同一文件为已有客户新建常规期权主配置，并导入一组两条有效的中间人明细、一组含一条无效比例的员工明细：主配置和有效组成功；员工组全部不执行，旧组不变；预览、执行结果、失败文件分别展示组结果和具体致错行。
2. 客户已有常规期权主配置时，“主配置”表仅有表头，“返佣/提成明细”表有记录：仅出现的客户+类型整组替换；未出现的类型及主配置字段均不修改。客户没有已有主配置、文件又未成功创建主配置时，明细组失败并提示“请先建立常规期权主配置”。
3. 同一客户同一类型可导入多条记录，允许同名；另一类型的合法组仍可执行。所有姓名均按手填文本处理，不匹配员工数据字典。
4. 比例 `0` 和 `100`、最多两位小数以及各明细类型对应的合法返佣规则均可通过；缺少姓名/比例/规则、比例越界、超过两位小数或规则与明细类型不匹配时该组失败，说明可为空。
5. 两表共 500 条数据行可进入预览，501 条被拦截；只计算数据行，不计表头。统计按两表数据行合计；失败组所有行计失败行数，执行项数按通过的主配置行数加通过的明细组数计算。

## 8. 孖展合约导入验收要点

1. 模板主配置仅有客户名称、孖展合约群编号、归属员工、直接对接人；明细仅有客户名称、明细类型、姓名、比例（%）、说明。六种具体明细类型分别可选，不出现返佣规则字段或该字段的校验。
2. 已有孖展合约主配置的客户可仅导入明细；新客户业务主配置与明细可在同一文件中先后成功。某类型含无效比例时该类型整组失败、旧组保留，主配置和其他有效类型仍成功；缺主配置提示先建立孖展合约主配置。
3. 所有姓名均按手填文本处理，不匹配员工数据字典。同客户同类型可多条，允许同名；同姓名跨类型合法。比例 `0`、`100` 和最多两位小数有效，缺值、越界或精度不符整组失败，说明允许为空。
4. 未出现的具体类型保持原值，已出现的具体类型整组替换；不得把中间人三种或员工三种合并为同一替换组。预览、执行结果和失败文件均按两表逐行统计，并展示组结果与致错 Excel 行；两表数据行合计最多 500。

## 9. 询价配置导入验收要点

1. “导入业务配置”可选择“询价配置”，切换后只展示该业务的单表字段：客户名称、报价分类ID、公司/中间人/行情额外加点分别对应大陆和香港六列；不混入合同业务群编号、返佣规则或返佣明细表。
2. 已有客户名称唯一匹配；同文件后续同名行提示“与第 X 条互斥”，先序行独立校验；不存在客户、报价分类ID未命中字典、百分比字段格式错误均按行失败，预览定位原始行号和具体原因。
3. 通过行新增或更新对应客户的询价配置，失败行不修改旧配置；更新行的空白加点字段不覆盖旧值，数值 `0` 不视为空。文件中心记录询价配置批次、通过/失败行数和逐行结果，修正文件作为新批次处理。
4. 执行后仅改变询价配置，不新增询价记录、不改变常规期权或孖展合约配置。正式百分比边界及新增空值规则按第 6 节确认后再补齐校验案例；原型中的示例报价分类ID仅用于演示，不作为真实字典值验收。

## 10. 统一业务配置窗口验收要点

1. 列表五个操作按钮的顺序、颜色和图标保留；前三个按钮分别进入询价配置、常规期权、孖展合约 Tab。同一客户反复打开仅有一个窗口和一个任务栏项目，不同客户可同时保留窗口。
2. 三个 Tab 均按第 2.4.1 节展示主配置字段；常规期权单独展示通道费率和税金；询价展示报价分类及六项地区加点，未配置时直接显示表单，无新建前置按钮，未填写关闭不产生配置或放弃确认；填写后支持草稿保护，保存成功后同步列表；孖展合约没有返佣规则字段。
3. 合同业务未配置、已配置、编辑主配置或编辑明细时，两处分区始终展示；常规期权四类、孖展合约六类明细均各有新增按钮，表单在点击类型下展开且类型固定，不出现类型选择下拉，规则选项与该类型匹配，保存只增加所属类型记录。不以先保存主配置为入口条件；无主配置时保存明细应提示先保存对应主配置，不写入明细且保留输入；补充并保存主配置后，原明细可以继续保存。导入缺少主配置时仍按原依赖规则处理。
4. 主配置两个人员字段都是【员工管理】下拉，两个字段使用同一字典，保存及再次编辑可回显选中值。明细姓名仍全部手填；同类型同名明细可新增多条并分别展示，只修改或删除其中一条不影响另一条；合法的 `0`、`100` 可保存，缺姓名、缺比例或规则不合法时保留输入并提示具体字段。
5. 详情、主配置编辑和明细录入在同一客户窗口内分区展示，不叠加完整子弹窗；保存或取消其中一处分区，另一处分区的草稿仍保留。切换 Tab 或关闭窗口时任一分区有未保存内容先短确认，继续编辑保留两处草稿，确认放弃后才切换或关闭；最小化和切换客户不丢草稿。
6. 宽屏并排、窄屏单窗时标题、三个 Tab、滚动内容及各分区保存/取消按钮均可访问；列表筛选和分页不因打开窗口而重置。原型只验证本地交互，真实字典、权限、文件解析及持久化另行验收。

## 表单、业务窗口与反馈

- 编辑控件白底、明确边框；只读内容采用标签与值的对齐布局。必填星号与具体错误原因同时出现，不能只靠红色边框反馈。
